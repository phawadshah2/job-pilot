# Tailoring playbook (for Claude)

Run after `python3 -m jobpilot find` (or `prepare`). Each prepared job has a folder
`~/.job-pilot/jobs/<company>/`:

| File | What |
|---|---|
| `jd.txt` | URL + the posting **verbatim**. Never edit. |
| `job.json` | key, company, title, score, gaps, keywords |
| `BRIEF.md` | JD keywords the candidate genuinely has (in the JD's wording) + gaps not to claim |
| `tailor.json` | **what you write** (below) |
| `cv.html` | rendered from the user's `cv.json` + your `tailor.json` by `jobpilot build` |

## Source of truth
`~/.job-pilot/facts.md` (generated by `jobpilot setup`): their skills, the skills they do **not**
have, unsure skills, every experience bullet with its id, projects and competency lines. It wins
over anything in a job posting. Never invent employers, dates, titles, metrics or skills.

## tailor.json
```json
{
  "headline": "Senior Flutter Engineer | Payments & Fintech | iOS & Android",
  "summary": "Plain text, rewritten around the JD's top 3-4 requirements, truthful.",
  "skills": ["lang", {"key": "backend", "text": "Firebase (Auth, FCM), REST APIs"},
             {"label": "Payments", "text": "Stripe, Apple Pay"}],
  "experience": {"<job id>": ["<bullet id>", "A truthful rewording of an existing bullet.", "<bullet id>"]},
  "project_order": ["<project id>"],
  "cover_letter": {"paragraphs": ["Why this role/company, in their words.",
                                  "Two or three proofs from facts.md that match their must-haves.",
                                  "Short close: availability, location/remote fit."]}
}
```
`cover_letter` is optional: plain text (blank lines between paragraphs) or `{"greeting", "paragraphs",
"closing"}`. Default greeting is "Dear <Company> Hiring Team,". 180–300 words, same honesty rules as
the CV (finalize checks it for skills they don't have).
- Ids come from facts.md and insert the user's own wording; any other string is used as written.
- Plain text only; `build` escapes it. Omitted fields keep the user's defaults.
- The design (fonts, layout, section order) is the project's and can't be changed per job.

## Hard rules
- **Never add a skill from "DON'T have"**, even if the JD demands it: `finalize` refuses the CV.
  "Unsure" skills are never claimed; list them in the report as questions for the user.
- **Metrics are fixed**: only numbers that already appear in facts.md, exactly as written.
- Dates, employers, job titles held and education never change.
- **2 pages max**, single column. If `finalize` says it's over, shorten wording and rebuild.

## How to tailor
1. **Headline**: mirror the JD's exact title first.
2. **Summary**: the JD's top requirements in its own vocabulary, where truthful. Mention location or
   remote readiness when relevant to the posting.
3. **Skills**: choose and order competency lines by relevance; add JD wording only for skills they have.
4. **Experience**: order bullets by relevance and reword with the JD's vocabulary; no new achievements.
5. **Projects**: most relevant first.

Then `python3 -m jobpilot build <key>`. It ends with a **reviewer pass** (`jobpilot critique <key>`):
`[fix]` = a JD keyword they have but the CV omits, or a number not in facts.md / the JD (fix and
rebuild); `[consider]` = generic opener, cliché, long summary, repeated phrase, company named only in
the greeting (say why them); `[gap]` = never add it, prepare an honest answer. Rebuilding keeps the previous PDFs in `versions/`. Aim for ≥ 80% coverage of the BRIEF keywords; the rest
should be genuine gaps.

## Report
Per job: `Company - Role`, score, coverage default→tailored, gaps (with an honest framing for an
interview), unsure skills to confirm, and both PDFs (CV + JD).

## Drafting application answers (after `apply`)
When a job folder has `questions.md`, you may draft `answers.json` (key = exact question text):
- Essay / motivation / "describe a time…" questions: truthful, from facts.md and the CV, 60–120 words,
  first person, specific to the JD.
- **Never answer for the user:** salary, notice period, nationality, visa status, relocation,
  references, relatives at the company, criminal record, demographics. List those back to them.
